Материал объясняет документированные роли и отношения. Акционеры АО, прямые финансовые потоки и часть договорных отношений не установлены; эти пробелы не заменяются гипотезами о контроле.

## Данные и редактирование

- `research/eia_media/data/research.json` — каноническая база, включая доказательные фрагменты и маршруты.
- Авторские Markdown-главы редактируются независимо и не перезаписываются экспортом.
- Справочники из JSON помечены как генерируемые; манифест защищает ручную правку от молчаливой потери.
- Вложения пользователя — исследовательские входы, а не автоматически проверенные факты. Проверка всех 44 внешних URL описана в SOURCE_REVIEW.md.

После изменения JSON:

```bash
python research/eia_media/tools/compile_research.py --write
npm run build
```

Если справочник редактировали вручную, экспорт остановится: сначала согласуйте правку с JSON. Исходный текст не удаляется автоматически.

## Локальный сайт и проверки

Для сборки достаточно Python 3.12. Приложение статическое, без серверного API. Markdown-it 14.1.0 с лицензией включена локально, CDN при чтении не нужен.

```bash
npm ci --cache /tmp/eia-npm-cache
npm run build
npm run test:pipeline
python -m http.server 8000 --bind 127.0.0.1 --directory research/eia_media/dashboard
```

В другом терминале:

```bash
npm run test:site
npm run test:reading
```

Браузерные проверки используют Chromium `/usr/bin/chromium`; другой путь задаётся `CHROMIUM_PATH`, адрес локального сервера — `EIA_TEST_URL`. Тесты проверяют читательские маршруты, доказательства, доступность всех текстов/досье, фильтры, мобильную компоновку и отсутствие автоматических внешних запросов. Тест изображения использует явно синтетическую фикстуру и не заявляет проверку доступности оригинала.

Для дополнительного сбора нужны `beautifulsoup4`, `pdftotext` и доступ к публичным источникам. Инструмент `tools/fetch.py` сохраняет метаданные и локальный кеш в `/tmp/eia-evidence`; путь меняется через `EIA_EVIDENCE_DIR`. Размер ответа ограничен 32 MiB. Сканы требуют OCR и проверки по изображению. Не публикуйте необработанные сканы с личными данными.

GitHub Pages настроен на ветку `gh-pages`, корень `/`. Публикуемое дерево — `research/eia_media/dashboard`; исходники и исследовательская история находятся в `master`.

## Читательские объяснения

Раздел `reader` в канонической базе содержит индивидуальные объяснения для всех досье и находок, словарь и цели открытых вопросов. Он отделён от исходных фактов и цитат. Проверка сборки требует полного покрытия досье и находок; не добавляйте вывод, которому нет опоры в исследовательских материалах.

Представление для читателя находится в `dashboard/reader.js`, `dashboard/reader-views.js` и `dashboard/reading.css`. Служебные параметры получения источников сохраняются в данных, но не выводятся в обычные карточки. Исходные материалы остаются доступны для скачивания. Дополнительные проверки `test:reading` оценивают полноту объяснений, точность цитат, словарь, клавиатурную навигацию, содержание глав и мобильную компоновку.
